# MaterixivYou App 规格

Status: ready-for-agent

日期：2026-10-04。规格版本：1.1。归属：独立 App 仓库。

本规格综合已确认的讨论、旧版 APK 与上游源码检查、Shaft 交互参考及详情页草图反馈。标为“建议默认”的细节用于形成完整实施方案，其调整记录随设计审阅与前置验证更新。测试边界已由用户确认：完整客户端使用场景为主，结合真机验收。

## Problem Statement

用户希望继续使用 MaterixivYou 的作品浏览体验，并获得持续可维护的新版客户端。旧版评论与小说使用流程出现兼容性问题；下载任务的组织和恢复能力需要加强；不同页面的收藏反馈分别采用即时变色与等待结果，操作进度需要更清楚地表达。

搜索需要可管理的单词条历史，帮助用户逐项组合多关键词模糊查询。界面与标签需要完整的中文呈现。账号凭证刷新应自动恢复原请求，维持用户当前浏览进度。

作品详情需要融合旧版横向翻图与 Shaft 式纵向图片浏览，通过设置切换图片区行为。作品标题、作者等信息常驻底部抽屉，收藏保持独立悬浮入口，并通过设备倾斜换边，服务单手使用场景。

用户同时希望交付一套完整、标准、可复用的 Avalonia Material 3 Expressive 控件库。正式客户端的布局、入口位置和视觉层级需要专门设计。

## Solution

交付新版 Android Pixiv 客户端，通过版本化包消费独立 M3 仓库发布的 M3 Expressive 控件。客户端提供完整的主要浏览流程、可靠的下载队列、统一的收藏处理中状态、可组合的搜索词条历史、中文界面与标签、自动恢复请求的登录状态管理，以及可配置的详情手势与重力换边。

作品详情以图片为视觉主体，底部常驻标题与作者，抽屉展开后呈现更多信息。收藏按钮保持独立悬浮与单手触达。浏览模式、重力开关及灵敏度等配置进入设置或次级菜单。

独立 M3 仓库负责完整标准控件、令牌、展厅、文档与包发布。本 App 在真实页面中验证其公开契约、主题切换与视觉一致性。

## User Stories

### 基础浏览与兼容性

1. 作为 Pixiv 用户，我希望通过正常登录流程建立账号会话，以便浏览与管理自己的作品收藏。
2. 作为浏览用户，我希望访问推荐、关注、排行、趋势与作者作品，以便延续旧版的主要使用习惯。
3. 作为浏览用户，我希望从列表进入作品详情并返回原位置，以便连续浏览作品。
4. 作为浏览用户，我希望查看作品标题、作者、标签及说明，以便理解作品并继续探索。
5. 作为评论读者，我希望打开插画与小说的评论入口，以便阅读作品讨论。
6. 作为评论读者，我希望继续加载评论并查看回复关系，以便完整阅读讨论。
7. 作为小说读者，我希望从小说入口访问推荐、关注、排行和搜索，以便找到想阅读的作品。
8. 作为小说读者，我希望打开正文并阅读章节、段落及插图，以便获得清楚的阅读体验。
9. 作为小说读者，我希望访问系列的相邻作品、收藏与书签，以便继续阅读。
10. 作为小说读者，我希望保存阅读位置并调整字号、行距与主题，以便在下次打开时继续阅读。

### 下载管理

11. 作为下载用户，我希望单张图片、多图作品和多件作品进入下载队列，以便集中安排下载。
12. 作为下载用户，我希望任务按作品归组并展示文件级进度，以便理解一部作品的下载状态。
13. 作为下载用户，我希望查看等待、进行中、暂停、失败和完成状态，以便选择下一步操作。
14. 作为下载用户，我希望暂停、继续与取消任务，以便控制网络与存储使用。
15. 作为下载用户，我希望批量操作选中的任务，以便高效管理大量作品。
16. 作为下载用户，我希望失败任务能够单独或批量重试，以便继续处理下载。
17. 作为下载用户，我希望一项任务失败时其他可运行任务继续推进，以便保持队列效率。
18. 作为下载用户，我希望网络恢复、进程重启后能恢复任务进度，以便继续完成作品保存。
19. 作为下载用户，我希望在系统允许的后台执行条件下继续下载并查看通知，以便切换到其他应用。
20. 作为下载用户，我希望识别已经保存和正在排队的同一资源，以便清楚处理重复下载。
21. 作为下载用户，我希望选择保存目录并配置命名方式，以便整理本地作品。
22. 作为下载用户，我希望完成后定位、打开或分享文件，以便使用保存的作品。
23. 作为下载用户，我希望任务记录清理与文件管理具有独立操作，以便准确控制本地数据。

### 收藏反馈

24. 作为收藏用户，我希望点击后立刻看到处理中状态，以便确认操作已开始。
25. 作为收藏用户，我希望请求结果决定最终收藏状态，以便准确理解账号中的收藏关系。
26. 作为收藏用户，我希望取消收藏也具有对应的处理中反馈，以便理解当前操作进度。
27. 作为收藏用户，我希望列表与详情同步显示同作品的收藏状态，以便在页面间获得一致反馈。
28. 作为收藏用户，我希望请求失败后恢复上一次稳定状态并提供重试，以便继续操作。
29. 作为收藏用户，我希望切换作品时各作品的提交结果分别归属正确的作品，以便持续浏览。

### 搜索词条历史

30. 作为搜索用户，我希望编辑多个关键词并执行模糊搜索，以便组合筛选条件。
31. 作为搜索用户，我希望一次搜索中的各词条分别进入历史，以便再次组合使用。
32. 作为搜索用户，我希望点击历史词条将它加入当前搜索，以便继续编辑查询。
33. 作为搜索用户，我希望通过明确的搜索操作提交查询，以便控制查询时机。
34. 作为搜索用户，我希望逐项删除、清空和固定历史词条，以便管理常用条件。
35. 作为搜索用户，我希望再次使用同一词条时更新其使用信息，以便快速找到最近使用的词。
36. 作为搜索用户，我希望处理重复词条并保留原始标签语义，以便得到清楚的当前搜索条件。
37. 作为搜索用户，我希望重启应用后继续使用历史记录，以便延续自己的搜索习惯。

### 中文呈现

38. 作为中文用户，我希望界面、设置、任务状态与错误反馈使用清楚的中文，以便理解所有操作。
39. 作为中文用户，我希望作品详情、搜索建议、趋势和作者页面统一呈现标签译名，以便识别标签。
40. 作为中文用户，我希望标签中译与原名保持可辨识的关系，以便搜索、复制和查看原始标签。
41. 作为中文用户，我希望已有标签译名能够被缓存并重复使用，以便获得稳定的显示体验。

### 会话恢复

42. 作为浏览用户，我希望 Token 过期后自动刷新并恢复原请求，以便继续当前操作。
43. 作为浏览用户，我希望同时出现的鉴权过期请求共享刷新结果，以便页面整体顺畅恢复。
44. 作为浏览用户，我希望恢复过程中保留内容、位置与已输入条件，以便延续浏览上下文。
45. 作为账号用户，我希望刷新结果需要重新登录时得到清楚的入口，以便恢复会话。

### 作品详情与单手操作

46. 作为看图用户，我希望选择横向分页或纵向浏览，以便使用适合自己的图片区行为。
47. 作为看图用户，我希望横向模式先翻当前作品图片，在边界继续切换相邻作品，以便延续旧版习惯。
48. 作为看图用户，我希望在下方信息区横向滑动直接切作品，以便快速浏览来源列表。
49. 作为看图用户，我希望标题与作者常驻，并通过抽屉展开标签及说明，以便随时理解当前作品。
50. 作为看图用户，我希望图片缩放、图片浏览、作品切换和抽屉拖动具有清楚的手势分工，以便流畅操作。
51. 作为单手用户，我希望收藏入口独立悬浮并吸附在可触达的一侧，以便方便点击。
52. 作为单手用户，我希望通过设备倾斜将收藏按钮换边，以便另一只手忙碌时继续收藏。
53. 作为单手用户，我希望换边后保留按钮位置，并通过反向倾斜再次换边，以便保持稳定的操作位置。
54. 作为单手用户，我希望配置重力功能与灵敏度，以便适配自己的握持方式。
55. 作为单手用户，我希望正在触摸或缩放时保持操作对象稳定，以便准确完成当前动作。

### 正式设计与主题包集成

56. 作为客户端用户，我希望正式界面具有清楚的信息层级与合适的入口位置，以便自然完成浏览、搜索和下载。
57. 作为客户端用户，我希望明暗主题、动态配色、中文字体放大和屏幕方向变化时保持清晰布局，以便适应设备与阅读习惯。
58. 作为使用读屏或键盘的用户，我希望控件具有正确语义与焦点反馈，以便访问主要功能。
59. 作为维护者，我希望拥有可重复的构建、发布与验收流程，以便持续修复接口兼容性并交付新版。

## Implementation Decisions

### 已确认的技术与组织方式

- 使用 C# 与 Avalonia 交付本 App，并通过明确的版本化包引用独立 M3 仓库的标准组件。
- M3 库与 App 使用两个独立 Git 仓库，各自维护规格、GitHub Issues、领域文档、版本和发布；App 通过版本化包依赖 M3 库。
- M3 仓库拥有标准令牌、通用组件、展厅、使用文档、兼容与包发布契约；App 仓库拥有 Pixiv 业务、原生平台适配、正式页面、AOT 与 Android 发布。
- 首期产品目标为 Android 手机与平板的核心使用路径；控件库按照 Avalonia 可复用组件设计。
- 采用现代 Avalonia、编译绑定与主题输入契约，标准控件的外观和状态由所引用的 M3 包提供。
- 客户端业务状态与主题令牌分别维护，收藏关系、搜索词条和下载任务采用领域模型表达。
- 后续调查、设计和实施由当前主代理直接推进。

### 构建与交付验证

- 建议采用 Avalonia 12 稳定补丁版及 .NET 10 作为起始构建基线，依赖版本在前置构建验证中锁定。
- Native AOT 作为目标交付方向；Satori 作为 GC 候选，在官方运行时对照下验证构建、启动、内存和稳定性。
- 第一项实施工作建立可重复的 Android 发布链，验证 AOT 运行时包、Bionic ABI、Java 互操作、签名包安装与真机启动，并据此确定运行时配置和支持设备矩阵。
- 数据序列化和服务创建采用可静态分析的方式，客户端及主题库持续进行裁剪与发布验证。

### 模块边界

- Pixiv 数据访问统一处理鉴权、响应适配、分页、错误分类和兼容性变化，对外提供稳定的客户端操作契约。
- 会话协调负责刷新与请求恢复；收藏协调负责每账号、每作品的稳定状态与处理中状态。
- 下载协调负责队列、文件传输、进度、恢复和持久化；各文件任务具有独立执行与失败状态，作品层负责归组呈现。
- 搜索历史负责单词条记录、使用信息与管理操作；标签呈现负责既有译名来源、缓存和原名关系。
- 详情交互负责图片区模式、起手区域、手势方向、图片边界和缩放优先级；重力换边负责倾斜输入与按钮锚点。
- 平台适配提供后台执行、文件与媒体访问、安全存储、链接回调、传感器和系统界面能力。

### 持久化与数据契约

- 下载记录保存资源标识、作品归属、输出配置、任务状态、已传输字节、远端版本信息和错误信息；资源去重以稳定的作品及图片身份和输出配置判定。
- 搜索历史保存原始词条、检索身份、最近使用时间、使用次数与固定状态；一次多词搜索分别更新各词条。
- 收藏状态以账号与作品为身份，处理中保存本次目标状态与上一次稳定状态，完成后广播确认结果。
- 阅读位置、图片位置和用户偏好具有可持久化的明确身份；恢复后定位到对应作品与内容。
- 登录凭证使用平台安全存储，诊断信息围绕操作类型、状态、耗时与错误分类记录。

### 下载行为

- 支持文件级与作品级任务管理，展示进度并提供暂停、继续、取消、重试与批量操作。
- 队列具备持久化、并发限制、重启恢复和后台执行适配；网络恢复后继续推进可运行任务。
- 续传根据远端 Range 与资源版本信息确定偏移；资源版本变化时重新建立对应传输。
- 文件完成检查通过后提交最终文件并标记完成；失败反馈可定位到具体任务。
- 任务记录清理保留完成文件，文件管理提供独立的显式操作。

### 收藏行为

- 状态流为稳定状态、处理中、结果确认后的稳定状态；添加与取消具有对称的反馈。
- 处理中立即可见，最终语义由请求结果确认；列表和详情共享状态。
- 请求失败时恢复上一次稳定状态并提供重试；传输结果需要确认时读取服务端收藏关系后收敛状态。
- 切换作品或页面后，请求结果继续归属原账号和作品。

### 搜索与中文

- 当前搜索以词条结构编辑，多关键词模糊搜索沿用现有语义。
- 搜索提交时分别记录各词条；点击历史追加到当前搜索，查询由显式搜索操作提交。
- 标签中文复用现有项目的译名能力或数据，优先核对现有客户端使用的 Pixiv 中文译名路径，并统一各页面的呈现。
- 界面、设置、任务状态与操作反馈使用本项目维护的中文文案资源。
- 原始标签身份服务于搜索和跳转；原名与中文译名形成清楚的展示关系。

### Token 刷新与请求恢复

- 根据响应状态与错误语义识别鉴权过期，原请求在刷新成功后自动恢复。
- 同一会话共享一次并发刷新，各等待请求按自身操作恢复；每次原请求的鉴权恢复具有明确次数边界。
- 请求恢复保留查询参数、操作内容与用户上下文；取消操作和账号变化参与恢复判定。
- 收藏等写操作在结果需要确认时读取服务端状态，以稳定关系收敛界面反馈。
- 刷新需要重新登录时进入清楚的会话恢复状态，并保留可继续的页面内容。

### 详情手势与重力换边

- 横向模式中，图片区优先浏览当前作品图片，边界向外手势交给相邻作品切换；信息区横向操作直接切作品。
- 纵向模式采用当前作品图片的纵向浏览，作品切换规则采用下方建议默认值。
- 标题和作者常驻信息抽屉，展开内容显示标签及说明；收藏入口独立悬浮。
- 手势按起手区域、锁定方向、图片边界和缩放状态分配；图像缩放优先完成当前平移与缩放操作。
- 重力输入控制收藏按钮位置，收藏操作由用户点击与服务结果决定；换边后保留锚点。
- 正在按住按钮、缩放图片或拖动抽屉时保持按钮位置；本页恢复交互后继续处理倾斜。
- 屏幕方向变化后重新映射倾斜方向，界面生命周期控制传感器订阅。

### 正式 UI 与主题包集成

- 正式详情页以作品为视觉主体，配置集中到设置或次级菜单；高保真设计覆盖详情、搜索和下载管理，并检查整体一致性。
- 图片区、常驻信息与悬浮入口的尺寸、间距和层级共同考虑系统安全区、单手触达和内容比例。
- M3 Expressive 的完整规范覆盖由独立 M3 仓库交付；App 对照其公开契约和包版本进行集成验证。
- App 使用 M3 的颜色、字体、形状、状态和动效令牌，并提供平台动态颜色与用户主题偏好。
- 正式客户端页面验证明暗主题、不同配色、字体尺度、触摸和读屏语义，采用相同的包组件与令牌。
- 动态配色由 Android 平台提供对应数据，自定义种子色依照 Material Color Utilities 的算法处理。

### 建议默认值

| 项目 | 建议默认 | 收敛方式 |
| --- | --- | --- |
| 下载基础能力 | 持久队列、暂停继续、独立重试、批量操作、归组、去重、后台与重启恢复 | 下载管理页面与场景验收 |
| 下载并发 | 初始 3 个文件任务，可通过设置调整 | 真机网络及资源测量 |
| 下载资源 | 静态图保存原图，多图逐文件保存，动图保存原始资源包与帧信息，小说导出 TXT | 格式验证与下载体验审阅 |
| 收藏重复点击 | 处理中保持本次操作，完成后接受下一次操作 | 状态与交互验收 |
| 搜索历史管理 | 最近使用排序、重复词条合并、删除、清空及固定 | 搜索页面审阅 |
| 纵向图片模式 | 同作品多图纵向连续浏览，横向切相邻作品；图片纵向边界保持当前作品 | 详情手势与高保真审阅 |
| 默认图片模式 | 延续旧版横向分页，可在设置切换纵向浏览 | 用户偏好设置 |
| 重力换边启用 | 通过设置手动启用，并保留固定左右位置配置 | 单手场景验收 |
| 重力触发 | 倾向哪侧就吸附哪侧，回正保留；约 25°、400ms 为实验起点 | 真机手感调试 |
| 抽屉高度 | 标题作者栏常驻，展开高度随内容和可用屏幕调整 | 多设备高保真审阅 |

## Testing Decisions

用户已确认以完整客户端使用场景为主要验收边界。自动化通过可控的 Pixiv 响应、持久化环境、时间与平台事件驱动真实客户端行为；真机补充手势、传感器、后台执行、系统存储和性能验证。

测试关注用户可观察结果、请求行为、文件结果与状态恢复。客户端场景层作为主要测试入口，数据访问和平台适配提供可替换的外部环境。必要的算法测试聚焦重力判定、手势分配和资源续传的边界。

现有参考材料包括旧版时间工具测试和交互草图的浏览器行为验证。草图已覆盖左右倾斜、回正后保留位置、收藏处理中与结果、图片边界切作品、抽屉展开及窄屏布局；正式验收扩展到真实 Avalonia 控件与 Android 平台。

## Out of Scope

本规格聚焦 Android 客户端与主题包消费。通用 M3 控件的完整实现、展厅、跨平台测试和独立包发布归属 M3 仓库规格；其他平台的完整客户端发布属于后续平台规格。

页面中文文案与标签译名构成本期中文能力。作品标题、简介及小说正文的内容翻译属于后续内容能力规格。

正式视觉方案、运行时组合和支持设备矩阵通过本规格中的设计与前置验证工作收敛，确定结果进入相应设计记录和 ADR。
